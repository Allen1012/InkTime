# 08 - 配置与部署

## 配置方式

**`.env` 是主要配置源**，`config/config.py` 已废弃（`config/config-example.py` 仅留作历史参考）。
生产 Web 部署另由 `deploy/inktime-server.service` 和 `deploy/docker-compose.yml` 明确覆盖
`APP_ENV=production`，防止本地模板的 `development` 默认值被带入生产。

```bash
cp .env.example .env
vi .env
```

四个入口脚本（分析、两个渲染、Web 应用工厂）都会自行 `load_dotenv()` 读取项目根的 `.env`，
所以直接执行时不需要先 `source .env`；systemd 通过 `EnvironmentFile=` 加载同一个文件，
再由单元文件强制生产模式。Web 服务只在调用 `src.server.app.create_app()` 时加载 `.env`，
模块 import 不创建 Flask 应用或运行目录。

### 优先级

```text
create_app(config_overrides) 显式覆盖 > 已存在的环境变量 > .env 文件 > 代码默认值
```

显式覆盖只用于临时数据库验证或嵌入调用，例如：

```python
from src.server.app import create_app

application = create_app({
    "DB_PATH": "/tmp/inktime-validation.db",
    "TESTING": True,
    "SECRET_KEY": "仅供当前临时验证的非生产值",
    "SESSION_COOKIE_SECURE": False,
})
```

不传覆盖时，部署行为仍是“已有环境变量优先于 `.env`”。分析脚本用
`load_dotenv(override=False)`，因此 `BATCH_LIMIT=20 python ...` 这类临时覆盖有效。

### 管理员安全配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| APP_ENV | development | 只允许 `development`、`testing`、`production`；其他值拒绝启动。systemd 与 Docker 的 Web 服务部署文件强制为 `production` |
| SECRET_KEY | 空 | 开发模式为空时仅在当前进程生成随机密钥且不记录；生产必须显式配置非空随机值，否则拒绝启动 |
| SESSION_COOKIE_HTTPONLY | True | 禁止客户端脚本读取会话 Cookie |
| SESSION_COOKIE_SAMESITE | Lax | 默认限制跨站携带会话 Cookie |
| SESSION_COOKIE_SECURE | 开发 False / 生产 True | 生产必须为 `True`，即使显式配置 `False` 也拒绝启动 |
| PERMANENT_SESSION_LIFETIME | 28800 | 永久会话有效期，单位秒 |
| WTF_CSRF_TIME_LIMIT | 3600 | 跨站请求伪造 token 有效期，单位秒 |
| ADMIN_LOGIN_MAX_FAILURES | 5 | 同一用户名和客户端地址组合的连续失败阈值 |
| ADMIN_LOGIN_FAILURE_WINDOW_SECONDS | 300 | 进程内连续失败窗口，单位秒 |

真实 `SECRET_KEY` 只写入部署环境或未入库的 `.env`，不得写入仓库、日志或文档。

### 迁移与创建管理员顺序

1. 先按现有备份流程生成一致性副本和基线。
2. 对明确指定的副本运行 `scripts/database_admin.py migrate` 和 `verify`，确认包含迁移 0003 与 `admin_users` 结构。
3. 确认目标环境的 `DB_PATH`、`APP_ENV` 和 `SECRET_KEY` 后，再安排正式库迁移。
4. 正式迁移完成后，按需交互创建管理员：

```bash
./venv/bin/flask --app src.server.app create-admin
```

命令交互读取用户名，隐藏输入并二次确认至少 12 个字符的密码；不会输出密码或哈希，也不会自动创建默认管理员。

### 编写 .env 的两个坑

- **含空格的值必须加引号**：`PROJECT_NAME="InkTime 相册"`。不加引号时
  `source .env` 会把值当命令执行，报 `相册: 未找到命令`。python-dotenv 和 systemd
  都能正确处理引号
- **`FONT_PATH` 留空等于没配字体**：空值会被解析成 `Path(".")`，
  `ImageFont.truetype(".")` 抛异常后静默退回 PIL 默认位图字体，中文全部渲染成豆腐块
  且不报错。必须显式指向一个中文字体文件

### 上传与 worker 配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| UPLOAD_MAX_FILES | 10 | 每批最大文件数 |
| UPLOAD_MAX_BYTES | 20971520 | 单文件最大字节数 |
| UPLOAD_MAX_PIXELS | 80000000 | 解码后最大像素数 |
| JOB_MAX_ATTEMPTS | 3 | 最大尝试次数 |
| JOB_LEASE_SECONDS | 120 | 任务租约秒数 |
| JOB_RENEW_SECONDS | 30 | 续租间隔秒数 |
| JOB_POLL_SECONDS | 2 | 空队列轮询间隔 |

独立 worker 入口为 `python -m src.analysis.run_worker`。它与 Web 服务读取相同的默认值和 `DB_PATH`；`JOB_MAX_ATTEMPTS` 会传给所有任务创建路径，固定上限仍为 3。Web 与 worker 启动都会拒绝 `JOB_RENEW_SECONDS >= JOB_LEASE_SECONDS`。运行账号需要写入上传目录与 SQLite 数据库。仓库没有宣称 Docker 或 systemd worker 已验证；部署时应另建常驻进程，不要把 worker 放入 Waitress Web 进程。

历史最终文件摘要通过受认证且受跨站请求伪造保护的 `POST /api/admin/jobs/backfill-content-hash` 创建。可传 `{"limit": 1000}`；重复活跃任务自动跳过。任务优先级低于上传、重新分析和旁白任务，可取消、可在工作进程停止后恢复，不调用视觉语言模型。

## 本地部署

### 环境准备

```bash
cd /path/to/InkTime

# 系统依赖（Linux）；缺 exiftool 不致命，但 GPS 会不全
sudo apt-get update && sudo apt-get install -y libimage-exiftool-perl

# 虚拟环境
python3 -m venv venv
./venv/bin/pip install --upgrade pip
./venv/bin/pip install -r requirements.txt
# 生产 WSGI 服务器，替代 Flask 开发服务器
./venv/bin/pip install waitress==3.0.2
```

验证：

```bash
exiftool -ver
./venv/bin/python -c "import flask, requests, PIL, dotenv; print('deps ok')"
./venv/bin/python -c "import waitress; print('waitress ok')"
```

### 配置

```bash
cp .env.example .env
# 至少设置 IMAGE_DIR、API_URL、MODEL_NAME、API_KEY、FONT_PATH、DOWNLOAD_KEY
```

### 运行

```bash
# 1. 分析照片（先小批量验证 prompt 效果）
BATCH_LIMIT=20 ./venv/bin/python src/analysis/analyze_photos_docker.py
# 或用封装脚本（自动加载 .env、用 venv python）
./scripts/run_analysis.sh

# 2. 全量分析（可随时中断，按 path 去重续跑）
nohup ./venv/bin/python src/analysis/analyze_photos_docker.py > logs/analyze_full.log 2>&1 &

# 3. 渲染今日照片
./venv/bin/python src/render/render_daily_photo.py

# 4. 启动服务器（开发用；生产见下方 systemd）
./venv/bin/python src/server/server.py
```

数据库结构由版本化迁移维护。运行分析前先执行 `scripts/database_admin.py migrate`，并且首次迁移必须指向活动数据库的一致性备份副本；分析入口只检查结构，不会在启动时静默补表。

### 回填存量数据

改了日期兜底规则或类型规范化规则后，存量照片不会自动跟上（分析脚本按 `path`
去重会跳过已分析照片）。用回填脚本处理，它不调用 VLM、不花额度：

```bash
./venv/bin/python scripts/backfill_metadata.py          # 预览，不写库
./venv/bin/python scripts/backfill_metadata.py --apply  # 实际写入
```

回填 `exif_datetime`、`date_source`、`exif_json.datetime`、`type` 四项。
执行前建议备份：`cp data/photos.db "data/photos.db.$(date +%F)"`。


## Docker 部署

Dockerfile 默认运行统一生产入口 `python -m src.server.run_server`。Compose 中的 Web 服务
明确设置 `APP_ENV=production`，覆盖 `.env.example` 面向本地开发的默认值；分析器不运行
Web 应用，因此不强制该变量。Compose 提供：

- `inktime-server`：常驻 Web 服务，`restart: unless-stopped`。
- `inktime-analyzer`：`tools` profile 下的一次性分析任务，不自动重启。

```bash
# IMAGE_DIR 在 Docker 部署时必须是宿主机绝对路径
DOCKER_BUILDKIT=1 docker compose --env-file .env -f deploy/docker-compose.yml config
DOCKER_BUILDKIT=1 docker compose --env-file .env -f deploy/docker-compose.yml build

docker compose --env-file .env -f deploy/docker-compose.yml up -d inktime-server
docker compose --env-file .env -f deploy/docker-compose.yml --profile tools run --rm inktime-analyzer
```

挂载规则：

- `data/` 读写挂到 `/app/data`，数据库固定为 `/app/data/photos.db`，输出为 `/app/data/output`。
- 照片目录只读挂载，且容器目标路径与宿主 `IMAGE_DIR` 的绝对路径完全相同。
- `logs/` 读写挂载。
- `.dockerignore` 排除 `.env`、数据库、日志、虚拟环境、Git 历史、Node.js 依赖和硬件产物。

<callout emoji="⚠️" background-color="light-yellow">SQLite 数据库不能放在服务器消息块或网络文件系统共享目录上；照片目录可以只读网络挂载。若数据库中的照片路径与容器挂载路径不一致，分析器可能把全部照片判断为不存在，因此禁止在路径预检通过前运行分析任务。</callout>

## systemd 服务部署

systemd、Docker 和本地生产环境统一执行：

```text
python -m src.server.run_server
```

仓库单元文件 `deploy/inktime-server.service` 的核心配置：

```ini
WorkingDirectory=/home/work/InkTime
EnvironmentFile=/home/work/InkTime/.env
Environment=APP_ENV=production
Environment=PYTHONPATH=/home/work/InkTime
ExecStart=/home/work/InkTime/venv/bin/python -m src.server.run_server
Restart=on-failure
RestartSec=3
```

按部署环境修改 `User`、`Group` 和路径；运行账号必须可读照片目录、可读写数据库及输出目录。

### 启用服务

```bash
sudo cp deploy/inktime-server.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now inktime-server
```

### 验证

```bash
systemctl is-active inktime-server                                   # active
systemctl is-enabled inktime-server                                  # enabled
curl -sS -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8888/     # 200
# 运行身份应是配置的账号而非 root
ps -o user=,cmd= -p "$(systemctl show -p MainPID --value inktime-server)"
# ESP32 下载接口：正确 key 应 200、错误 key 应 404
curl -sS -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:8888/static/inktime/$DOWNLOAD_KEY/latest.bin"
curl -sS -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:8888/static/inktime/wrongkey/latest.bin"
# 局域网 IP
ip -4 -o addr show scope global | awk '{print $4}'
```

如防火墙拦截局域网访问，只开放实际网段，**不要**开放 `any`：

```bash
sudo ufw allow from 192.168.0.0/16 to any port 8888 proto tcp
```

### 日志

```bash
journalctl -u inktime-server -f --since "10 min ago"
```


## 定时任务

### 每日渲染（crontab）

```bash
chmod +x scripts/daily_render.sh
crontab -e
# 加入（每天凌晨 5 点渲染）
0 5 * * * /home/work/InkTime/scripts/daily_render.sh
```

改 crontab 前先备份：`crontab -l > ~/crontab.backup.$(date +%F)`。

### daily_render.sh 说明

- `PROJECT_DIR` 按脚本自身位置自动推导，不需要手改路径
- 用目录锁（`mkdir tmp/inktime_render.lockdir`）防止并发执行，
  重复触发会写入 `another render is running, skip.` 并以 0 退出
- `trap cleanup EXIT INT TERM` 保证异常退出时释放锁
- 检查 venv 与 `.env` 是否存在（旧版检查的是 `config.py`）
- 日志输出到 `logs/render.log`

### 验证

```bash
./scripts/daily_render.sh && tail -20 logs/render.log
# 连续跑两次，第二次应输出 "another render is running, skip."
crontab -l | grep daily_render
```

cron 的环境变量极少（PATH 通常只有 `/usr/bin:/bin`），建议按 cron 环境实测一次：

```bash
env -i HOME="$HOME" LOGNAME="$USER" PATH=/usr/bin:/bin SHELL=/bin/sh \
  /home/work/InkTime/scripts/daily_render.sh
```

脚本内部使用绝对路径的 venv python 并自行加载 `.env`，因此不依赖 PATH。

## 安全建议

1. **DOWNLOAD_KEY**：改成随机字符串，防止照片被随意访问
2. **同步 ESP32**：修改 DOWNLOAD_KEY 后，同步修改固件中的 `DAILY_PHOTO_PATH_PREFIX`
3. **WebUI 无鉴权**：`FLASK_HOST=0.0.0.0` 时同网段任何设备都能浏览全部照片、文案和
   GPS 信息。网络环境不完全可信时，把 `FLASK_HOST` 改成具体内网 IP，或加 Basic Auth
4. **公网部署**：必须加 HTTPS 反代（nginx）+ 鉴权，或限制内网访问
5. **WebUI**：跑通后建议关闭（`ENABLE_REVIEW_WEBUI=False`），只留 ESP32 下载接口
6. **目录浏览**：`ENABLE_FILE_BROWSER` 保持 `False`
7. **API_KEY**：如使用云端 VLM，妥善保管密钥；`.gitignore` 已包含 `.env`。
   密钥若曾出现在文档、聊天记录等处，应在平台上重置
8. **日志**：`logs/` 下的分析日志包含照片绝对路径和全部描述文案，已加入 `.gitignore`

> 改完 `.env` 需要 `sudo systemctl restart inktime-server` 才生效，
> systemd 只在启动时读一次 `EnvironmentFile`。

> `.env` 不入库，新增配置项务必同步到 `.env.example` —— 那是唯一入库的配置模板。
> 模板里值含空格必须加引号（如 `PROJECT_NAME="InkTime 相册"`），否则 `source` 会报错。
