# 04 - 图片渲染模块

## 概述

图片渲染模块负责从数据库中选出「历史上的今天」照片，渲染为墨水屏可直接显示的格式。

**核心文件**：`src/render/render_daily_photo.py`

## 选片算法

### 候选池的前置过滤（重要）

进入选片逻辑之前，`load_sim_rows()` 会先做两道硬过滤，**不满足的照片会被彻底排除**：

1. `exif_json` 中解析不出拍摄日期的照片直接跳过（`if not date_str: continue`）
2. 路径含 `screenshot` 的照片直接跳过

这意味着：**没有 EXIF 拍摄时间的照片永远不会被展示**，回溯 365 天和全局兜底都救不了它们，
因为它们根本没进候选池。常见的无 EXIF 来源包括截图、微信保存的图、部分导出/压缩过的照片、
AI 生成图。

所以「只要库非空就一定选得出图」是错的，正确的前提是「库里有能解析出拍摄日期的照片」。
分析完相册后应检查这个比例：

```bash
./venv/bin/python -c "
import sqlite3
c = sqlite3.connect('data/photos.db').cursor()
tot = c.execute('SELECT COUNT(*) FROM photo_scores').fetchone()[0]
ok = c.execute(\"SELECT COUNT(*) FROM photo_scores WHERE exif_datetime IS NOT NULL AND exif_datetime != ''\").fetchone()[0]
print(f'可用 {ok}/{tot}')
"
```

比例过低时，装 exiftool 能补回一部分（PIL 读不到的 EXIF 段），但被彻底抹掉 EXIF 的照片
无法恢复。

### 核心逻辑：「历史上的今天」

```
1. 获取今天的月日（如 12-02）
2. 在数据库中查找所有年份该月日的照片（仅候选池内的）
3. 筛选 memory_score > MEMORY_THRESHOLD 的候选
4. 随机选择 DAILY_PHOTO_QUANTITY 张（默认 5 张）
5. 如果该月日没有符合条件的照片：
   → 往前回溯一天（12-01, 11-30, ...）
   → 最多回溯 365 天
6. 如果 365 天都没有：
   → 兜底选择全局 memory_score 最高的照片
```

### 全局补足（FILL_FROM_GLOBAL）

命中的那一天照片总数不足 `DAILY_PHOTO_QUANTITY` 时，原逻辑只从**同一天**补，
凑不满就少出几张 bin。相册照片少时几乎每天都凑不满，而 ESP32 会随机取
`photo_{0..4}.bin`，缺失的槽位会读到前几天的旧文件。

`FILL_FROM_GLOBAL=True`（默认）时改为从全局按 `memory_score` 降序补足到
`DAILY_PHOTO_QUANTITY` 张，日志打印「从全局补足: N 张」。照片够多之后可关掉，
让选片严格贴合「历史上的今天」。

日志会打印 `回溯天数(day_offset)`、`使用兜底全局最大`、`从全局补足`，据此判断：

- `使用兜底全局最大` 经常为 `True` → `MEMORY_THRESHOLD` 该调低
- `从全局补足` 经常不为 0 → 相册在该日期附近照片太少


### 日期匹配方式

- 从 `exif_json` 字段解析拍摄日期（YYYY-MM-DD）
- 提取月日部分（MM-DD）进行匹配
- 使用 day-of-year 进行回溯计算（基于非闰年 365 天）

### 配置项

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| MEMORY_THRESHOLD | 70.0 | 选片最低回忆度阈值 |
| DAILY_PHOTO_QUANTITY | 5 | 每日选片数量 |

## 渲染流程

### 画布布局（480×800 竖屏）

```
┌────────────────────────┐ ← 0
│                        │
│                        │
│      照片区域           │  高度 = 800 - 100 = 700px
│   （铺满裁剪）          │
│                        │
│                        │
├────────────────────────┤ ← 700
│  文案（最多两行）        │
│  日期          地点     │  高度 = 100px（TEXT_AREA_HEIGHT）
└────────────────────────┘ ← 800
```

### 照片处理

1. 加载原图 → EXIF 方向纠正 → 转 RGB
2. 铺满裁剪（Cover Crop）：缩放到至少覆盖区域，从中心裁剪
3. 贴到画布上方区域

### 文字渲染

- 字体：`FONT_PATH` 指定的 TTF/TTC 文件。**加载失败会静默退回 `ImageFont.load_default()`，
  该字体不含中文字形，文案会渲染成豆腐块且不报任何错误**。`FONT_PATH` 留空时
  `Path("")` 会变成 `Path(".")`，同样触发这个退回，所以必须显式配置。
  Ubuntu 上可用 `/usr/share/fonts/opentype/noto/NotoSansCJK-Regular.ttc`

- 文案：22px，最多两行，中文按字符宽度折行
- 日期：20px，格式 "YYYY.M.D"（去掉前导零）
- 地点：20px，右对齐；优先显示城市名，无城市则显示经纬度

## 四色抖动算法

### 调色板

| 索引 | 颜色 | RGB 值 |
|------|------|--------|
| 0 | 黑 | (0, 0, 0) |
| 1 | 白 | (255, 255, 255) |
| 2 | 红 | (200, 0, 0) |
| 3 | 黄 | (220, 180, 0) |

### Floyd-Steinberg 抖动

对每个像素：
1. 加上累积误差
2. 找到最近的调色板颜色（欧氏距离）
3. 计算误差 = 原始值 - 量化值
4. 将误差扩散到相邻像素：
   - 右方：7/16
   - 左下：3/16
   - 正下：5/16
   - 右下：1/16

## 输出格式

### BIN 文件

- 大小：480 × 800 = 384,000 字节
- 编码：1 字节/像素，值为调色板索引（0-3）
- 排列：行优先，从上到下、从左到右

### H 头文件

```c
// Auto-generated from render_daily_photo.py
// Size = 384000 bytes (480x800, 1 byte/pixel)

const unsigned int daily_bin_0_size = 384000;
const uint8_t daily_bin_0[] = {
    0x01, 0x01, 0x01, ...
};
```

### 输出文件列表

| 文件 | 说明 |
|------|------|
| `photo_0.bin` ~ `photo_4.bin` | 每日渲染的多张照片 |
| `photo_0.h` ~ `photo_4.h` | 对应的 C 头文件数组 |
| `preview_0.png` ~ `preview_4.png` | 抖动后的预览图 |
| `latest.bin` | photo_0.bin 的副本（兼容旧流程） |
| `latest.h` | photo_0.h 的副本 |
| `preview.png` | preview_0.png 的副本 |

## 13.3 寸六色版本

项目还包含 13.3 寸六色屏的渲染变体（`render_daily_photo_133c.py`），主要区别：
- 分辨率：1200×1600
- 颜色：6 色（黑/白/红/黄/蓝/绿）
- 输出分为左右两半（_L.bin / _R.bin），适配双芯片驱动
