# 09 - 开发指南

## 本地开发环境搭建

### 前置条件

- Python 3.10+
- VLM 服务（如 LM Studio + Qwen3-VL-32B）
- 一些测试照片

### 快速开始

```bash
# 1. 克隆项目
git clone <repo-url>
cd InkTime

# 2. 创建虚拟环境
python3 -m venv venv
source venv/bin/activate

# 3. 安装依赖（已包含固定版本 Waitress）
pip install -r requirements.txt

# 4. 配置（.env 是唯一配置源）
cp .env.example .env
# 编辑 .env：至少设置 IMAGE_DIR、API_URL、MODEL_NAME、API_KEY、FONT_PATH

# 5. 数据库和路径预检
./venv/bin/python scripts/database_admin.py preflight --env-file .env

# 6. 用 SQLite backup API 创建一致性备份与身份基线
./venv/bin/python scripts/database_admin.py backup \
  --database data/photos.db --output-dir data/backups

# 7. 只在备份副本上首次演练迁移与严格验证
./venv/bin/python scripts/database_admin.py migrate --database /absolute/path/to/backup.db
./venv/bin/python scripts/database_admin.py verify \
  --database /absolute/path/to/backup.db \
  --baseline /absolute/path/to/backup.baseline.json

# 8. 审批后对受控目标显式迁移，再用只读门禁确认结构
./venv/bin/python scripts/database_admin.py migrate --database /absolute/path/to/target.db
./venv/bin/python scripts/database_admin.py check-schema --database /absolute/path/to/target.db

# 9. 准备视觉大模型：本地 LM Studio，或直接填云端 OpenAI 兼容 API

# 10. 运行分析（入口只检查当前结构，不自动迁移；建议先设 BATCH_LIMIT=3）
BATCH_LIMIT=3 ./scripts/run_analysis.sh

# 11. 启动独立后台工作进程
./venv/bin/python -m src.analysis.run_worker

# 12. 渲染
./scripts/daily_render.sh

# 13. 启动生产服务器
./venv/bin/python -m src.server.run_server
# 访问 http://127.0.0.1:5005/（端口取 .env 的 FLASK_PORT）
```

### 数据库管理与运行入口边界

| 命令 | 是否写数据库或文件 | 用途 |
|------|--------------------|------|
| `database_admin.py preflight` | 否 | 检查路径、权限、挂载点及异常照片路径 |
| `database_admin.py baseline` | 写基线 JSON | 记录迁移前照片身份与数据库状态 |
| `database_admin.py backup` | 写备份数据库和基线 JSON | 使用 SQLite backup API 创建一致性副本，并把目标切换为独立 DELETE 日志模式 |
| `database_admin.py migrate` | 是 | 仅升级显式 `--database` 指定的数据库 |
| `database_admin.py check-schema` | 否 | 调用 `assert_current_schema()` 的只读门禁；成功输出目标版本 45、迁移数量、最大迁移版本和 `schema_current` |
| `database_admin.py verify` | 否 | 严格检查连续 1 至 45、完整性、外键、忙等待、关键结构和照片身份基线 |
| `python -m src.server.run_server` | 运行期按请求读写 | 启动 Web 服务，只检查结构，不迁移 |
| `python -m src.analysis.run_worker` | 运行期处理任务 | 启动独立工作进程，首次认领时固化配置快照，只检查结构，不迁移 |

严格 `verify` 只有在 `integrity_check` 与 `quick_check` 都为 `ok`、外键开启且无违规、`busy_timeout=5000`、关键字段和管理员表结构存在、迁移版本恰好连续 1 至 45、六项照片身份不变量一致时才成功。

## 代码结构说明

### src/analysis/analyze_photos_docker.py

| 函数 | 职责 |
|------|------|
| `main()` | 主流程：扫描 → 过滤 → 清理 → 逐张分析 |
| `call_vlm(path)` | 调用 VLM 获取描述和评分 |
| `generate_side_caption(path)` | 调用 VLM 生成一句话文案 |
| `read_exif(path)` | 提取 EXIF 信息 |
| `encode_image_to_b64(path)` | 图片预处理 + Base64 编码 |
| `find_nearest_city(lat, lon, ...)` | GPS 逆地理编码 |
| `list_images(limit)` | 递归扫描图片文件 |
| `filter_unscored(conn, paths)` | 筛选未分析的照片 |
| `assert_current_schema(DB_PATH)` | 启动前确认版本化迁移已提供必要表和字段，不在分析流程静默改表 |

### src/render/render_daily_photo.py

| 函数 | 职责 |
|------|------|
| `main()` | 主流程：加载数据 → 选片 → 渲染 → 输出 |
| `choose_photos_for_today(items, today, count)` | 选片算法 |
| `render_image(item)` | 渲染单张照片到 480×800 画布 |
| `apply_four_color_dither(img)` | Floyd-Steinberg 四色抖动 |
| `image_to_palette_bin(img)` | 图像转 BIN 格式 |
| `write_h_array(bin_path, h_path)` | 生成 C 头文件 |
| `load_sim_rows()` | 从数据库加载照片数据 |

### src/server Web 服务分层

| 文件 | 职责 |
|------|------|
| `app.py` | 每次创建独立 Flask 应用；加载配置覆盖；注册数据库 teardown、Service、Blueprint 和错误处理 |
| `blueprints/public.py` | 现有 27 条显式公开路由，只解析请求、调用 Service、转换响应 |
| `blueprints/admin.py` | `/admin` 登录、退出和页面路由，以及 `/api/admin` 接口；两个后台 Blueprint 默认要求认证并保护写请求 |
| `services.py` | 照片序列化、设置读取、媒体边界、展示、面板、设备下载和目录浏览行为 |
| `repositories/photo_repository.py` | 照片只读 SQL；值参数化，排序走服务端白名单 |
| `service_contracts.py` | 认证、任务、审计的 `typing.Protocol` 扩展接口 |
| `errors.py` | 页面错误页和安全 JSON 错误响应；未知异常只在服务端记录上下文 |
| `server.py` | 兼容旧的直接执行和 `src.server.server:create_app` 导入路径 |

依赖方向固定为 Blueprint → Service → Repository → `src.database`。普通请求连接放在
Flask `g` 中并由应用 teardown 关闭；`gallery.py` 的独立短写事务保持不变。

## 调试技巧

### 分析模块调试

1. **设置 BATCH_LIMIT=1**：只处理一张照片，快速验证流程
2. **查看 VLM 输出**：脚本会打印每张照片的分析结果
3. **跳过文案生成**：注释掉 `generate_side_caption` 调用可加速测试
4. **检查数据库**：`sqlite3 data/photos.db "SELECT id, memory_score, side_caption FROM photo_scores LIMIT 5;"`
   没装 sqlite3 CLI 时用：
   `./venv/bin/python -c "import sqlite3;print(sqlite3.connect('data/photos.db').execute('SELECT id,memory_score,side_caption FROM photo_scores LIMIT 5').fetchall())"`
5. **确认候选池**：没有 EXIF 拍摄时间的照片不会进选片候选池，
   用 `SELECT COUNT(*) FROM photo_scores WHERE exif_datetime IS NOT NULL AND exif_datetime != ''` 看比例

### 渲染模块调试

1. **查看预览图**：`data/output/preview_0.png` 是抖动后的效果
2. **调整阈值**：降低 MEMORY_THRESHOLD 可以让更多照片被选中
3. **指定日期测试**：修改 `TODAY = dt.date(2024, 12, 2)` 测试特定日期

### 服务器调试

1. **Flask debug 模式**：直接跑 `python src/server/server.py` 并把 `app.run(debug=True)`，仅用于本地调试；常驻请用 waitress
2. **API 测试**：`curl "http://127.0.0.1:8888/api/photos?page=1&limit=3"`
3. **ESP32 模拟**：`curl -o test.bin "http://127.0.0.1:8888/static/inktime/$DOWNLOAD_KEY/photo_0.bin"`

### 后台任务调试

只使用临时数据库和临时 `IMAGE_DIR` 验证任务，不调用真实模型。迁移加载器会拒绝空 SQL 或一份文件多条 SQL。推荐用注入的假分析函数调用 `AnalysisWorker.run_once()`，覆盖两个连接原子认领、照片 pending→running→succeeded、照片取消后 failed 且 `analysis_error=job_canceled`、普通失败、取消与完成竞态、租约恢复、旧工作进程晚完成、三次失败和管理员编辑版本冲突。后台任务取消后的 `admin_jobs.status` 仍为 canceled。

上传验证应创建带拍摄时间与 GPS 的临时照片，确认重编码后任务仍使用原始拍摄语义、数据库摘要等于正式文件字节；同时覆盖 SHA-256 去重、第三张非法时前两张不落库不落盘、数据库提交失败补偿、系统专属孤儿临时文件清理及 SQLite 锁定时无半记录。历史摘要回填要验证稳定照片编号、低优先级让出、取消、恢复和不调用视觉语言模型。认证验证继续覆盖匿名访问、登录与跨站请求伪造保护。

### 阶段 6 回收站与维护任务调试

只使用 `/tmp` 下的新数据库、照片目录和输出目录验证，不迁移正式 `data/photos.db`，也不要触碰
`data/photos.db-shm` 与 `data/photos.db-wal`。推荐覆盖以下边界：

1. 活动照片路径必须位于 `IMAGE_DIR`，`.trash` 路径不能走公开媒体端点；
2. 软删除后原文件消失、回收站实际路径存在、`blocked=1` 且只有一个活跃 `render_display`；
3. 重复删除返回冲突，恢复目标存在返回冲突；
4. 在 `soft_delete_before_commit` 和 `restore_before_commit` 注入失败，文件必须反向补偿；
5. 永久删除必须同时满足回收站状态、确认文本和 `expected_version`，回收站文件已缺失时仍能幂等清库；
6. 清理预览前后审计数量不变，执行任务逐项保存 `succeeded/failed/skipped` 和生命周期审计；
7. 在 `render_before_publish` 注入失败，设备下载和 `/files/` 必须持续被屏蔽；重试成功后 manifest 保存且解除屏蔽；
8. 让续租返回 `False` 或抛出数据库异常，释放假渲染阻塞点后断言旧正式文件字节完全不变，任务未完成且仍保持屏蔽；
9. 让工作进程甲的租约过期，由工作进程乙恢复并重新领取，再释放甲继续执行，断言甲不能进入正式发布、乙可以发布；过期但尚未恢复的任务也不能续租或完成；
10. 工作进程遇到未知照片任务或维护任务类型必须稳定失败，不能调用照片分析函数。

渲染验证可以在 `/tmp` 注入只生成最小假产物的两套 `main`，验证临时目录、事务所有权栅栏内逐文件 `os.replace`、失租时旧正式文件不变、失败保持 blocked 和成功保存 manifest，不需要调用真实模型，也不改变选片算法。公开前端安全回归应向旁白、分类、相机型号、照片文件名和无效拍摄时间写入 `<img src=x onerror=...>` 及引号闭合文本，断言页面只显示字面文本、没有新增脚本或攻击图片节点，媒体地址仍限制在预期同源接口。

## 常见问题

### Q: VLM 返回非 JSON 格式

**原因**：模型未严格遵循 JSON 输出指令
**解决**：
- 确认使用支持视觉的模型（如 qwen3-vl）
- 检查 temperature 设置（分析用 0.2，文案用 0.7）
- 查看 `[DEBUG] 非 JSON 输出` 日志

### Q: GPS 信息缺失

**原因**：PIL 无法解析某些格式的 GPS 数据
**解决**：安装 exiftool（`brew install exiftool`），脚本会自动使用

### Q: 渲染时找不到照片

**原因**：数据库中的绝对路径与实际文件或容器挂载路径不匹配
**解决**：
- 先运行 `./venv/bin/python scripts/database_admin.py preflight --env-file .env`
- 检查输出中的 `photo_paths.outside_image_dir` 与 `photo_paths.missing_files`
- 修正 `IMAGE_DIR`、容器同路径挂载或缺失文件后再渲染
- 分析入口不会自动清理不存在的照片记录，不要把重新分析当作路径修复手段

### Q: ESP32 下载失败

**排查步骤**：
1. 确认服务器运行中：`curl http://server:8888/`
2. 确认 DOWNLOAD_KEY 匹配
3. 确认 .bin 文件存在：`ls data/output/photo_*.bin`
4. 检查 ESP32 串口日志

### Q: 墨水屏不显示

**排查步骤**：
1. 检查 SPI 接线（6 根信号线）
2. 串口是否有 "BUSY timeout" 错误
3. 确认 PSRAM 已启用（Arduino IDE 设置）
4. 确认 .bin 文件大小为 384,000 字节

## 扩展开发

### 添加新屏幕支持

1. 修改 `CANVAS_WIDTH` / `CANVAS_HEIGHT`
2. 调整 `TEXT_AREA_HEIGHT` 和字体大小
3. 修改调色板（如 6 色屏需要扩展 PALETTE）
4. 更新 ESP32 固件中的屏幕构造函数

### 修改评分逻辑

编辑 `analyze_photos_docker.py` 中的 `system_prompt`：
- 调整分数区间定义
- 修改加分/减分规则
- 添加新的照片类型

### 修改文案风格

编辑 `generate_side_caption` 函数中的 `system_prompt`：
- 调整创作原则
- 修改禁用词列表
- 改变风格方向

### 添加新的 Web 页面

1. 在 `src/server/templates/` 下创建模板；公开页面路由加到 `blueprints/public.py`，后台页面加到 `blueprints/admin.py`
2. Blueprint 只解析请求和转换响应，业务行为写入 `services.py`
3. 新增照片数据库查询时写入 `repositories/photo_repository.py`，所有值参数化；动态排序必须使用服务端白名单
4. 在 `app.py` 的 `_register_services()` 注册新增 Service；模板中的 Blueprint 端点使用 `url_for('public.<端点>')`
5. 前端 JavaScript 放在 `src/server/static/js/`；除非明确做接口版本升级，否则保持既有 URL 不变

阶段 2 若实现登录、任务和审计，优先实现 `service_contracts.py` 中的 `AuthService`、
`JobService`、`AuditService` 协议，不要把认证逻辑塞回公开设置接口。

## 项目约定

- Python 代码使用 UTF-8 编码
- 数据库操作后立即 commit（保证断点续跑）
- 配置项统一从 `.env` / 环境变量读取，不要新增 config.py 依赖
- ESP32 固件中的 DOWNLOAD_KEY 必须与服务端同步
- 渲染输出覆盖旧文件（不保留历史版本）
