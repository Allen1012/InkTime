# 02 - 系统架构

## 四大模块

InkTime 由四个核心模块组成，各自独立运行，通过 SQLite 数据库和文件系统协作。

## 数据流

### 完整数据流向

1. **照片输入** → `analyze_photos.py` 扫描 IMAGE_DIR
2. **AI 分析** → 调用 VLM API，获取描述、分类、评分
3. **EXIF 提取** → PIL + exiftool 获取拍摄时间、GPS、相机信息
4. **城市解析** → 本地 CSV 数据库将 GPS 坐标转为中文城市名
5. **文案生成** → 再次调用 VLM 生成一句话旁白文案
6. **数据库写入** → 所有结果存入 `photo_scores` 表
7. **每日选片** → `render_daily_photo.py` 按月日匹配 + 评分筛选
8. **图像渲染** → 照片 + 文案 + 日期 + 地点 → 480×800 画布
9. **四色抖动** → Floyd-Steinberg 算法量化为黑/白/红/黄
10. **BIN 输出** → 行优先、1字节/像素的二进制文件
11. **ESP32 下载** → HTTP GET 获取 .bin 文件
12. **墨水屏刷新** → SPI 驱动写入像素数据

### 运行时序

```
[每天一次 - crontab 触发]
  render_daily_photo.py
    → 读取数据库
    → 选片（历史上的今天）
    → 渲染 + 抖动
    → 输出 photo_0.bin ~ photo_4.bin

[常驻运行 - systemd 服务]
  server.py
    → 监听 5005 端口
    → 提供 ESP32 下载接口
    → 提供 Web 浏览界面

[每天定时唤醒 - ESP32 Deep Sleep]
  ink-display-7C-photo.ino
    → 连接 WiFi
    → NTP 同步时间
    → 随机选一张 photo_{0-4}.bin 下载
    → 刷新墨水屏
    → 进入 Deep Sleep

[按需运行 - 手动或定时]
  analyze_photos.py
    → 扫描新照片
    → 跳过已分析的
    → 逐张调用 VLM
    → 写入数据库
```

## 模块间接口

### 数据库接口（photo_scores 表）

所有模块通过 SQLite 数据库 `photo_scores` 表交换数据：
- **写入方**：analyze_photos.py
- **读取方**：render_daily_photo.py, server.py

### 文件系统接口

| 路径 | 生产者 | 消费者 | 格式 |
|------|--------|--------|------|
| `data/output/photo_{idx}.bin` | render_daily_photo.py | server.py → ESP32 | 二进制，480×800 字节 |
| `data/output/preview_{idx}.png` | render_daily_photo.py | server.py → Web | PNG 图片 |
| `data/output/photo_{idx}.h` | render_daily_photo.py | ESP32 编译（可选） | C 头文件数组 |
| `data/output/latest.bin` | render_daily_photo.py | 兼容旧流程 | 同 photo_0.bin |

### HTTP 接口

| 端点 | 方法 | 消费者 | 说明 |
|------|------|--------|------|
| `/static/inktime/{key}/photo_{idx}.bin` | GET | ESP32 | 下载渲染后的照片 |
| `/api/photos` | GET | Web 前端 | 照片列表（分页、筛选、排序） |
| `/api/photo/<id>` | GET | Web 前端 | 照片详情 |
| `/api/search` | GET | Web 前端 | 搜索照片 |
| `/api/category/stats` | GET | Web 前端 | 分类统计 |
| `/api/display/next` | GET | 展示页面 | 下一张照片 |
| `/display` | GET | 浏览器 | 沉浸式展示页面 |

## 配置层级

```
环境变量（最高优先级）
    ↓ 覆盖
config/config.py（Python 模块）
    ↓ 覆盖
代码中的默认值（最低优先级）
```

- `analyze_photos.py`：从 `config.py` 读取，允许环境变量覆盖部分字段
- `analyze_photos_docker.py`：纯环境变量驱动，适合 Docker
- `render_daily_photo.py`：从 `config.py` 读取
- `server.py`：先尝试 `.env`，再尝试 `config.py`，最后用默认值
