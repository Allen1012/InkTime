# 01 - 项目概览

## 项目定位

InkTime 是一个 AI 驱动的墨水屏电子相框项目。它不是简单的随机播放相册，而是：

1. 用视觉大模型（VLM）理解每张照片的内容
2. 为照片打分（值得回忆度 + 美观度）并生成一句话文案
3. 每天从「历史上的今天」中选出最值得回忆的照片
4. 渲染为墨水屏可显示的格式，推送到 ESP32 硬件
5. 同时提供 Web 端浏览和沉浸式展示页面
6. 通过受保护的后台上传入口和独立 worker 持久化执行分析任务

## 核心价值

- **智能选片**：基于 AI 评分的「历史上的今天」，而非随机播放
- **低功耗**：Deep Sleep 待机 < 1mA，5000mAh 电池约半年续航
- **离线友好**：GPS 逆地理编码使用本地城市数据库
- **断点续跑**：照片分析支持中断后继续，不重复处理
- **多端体验**：墨水屏硬件 + Web 浏览 + 沉浸式展示页面

## 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| AI | Qwen3-VL-32B（或任何 OpenAI 兼容 VLM） | 照片内容理解与评分 |
| 后端 | Python 3.10+, Flask 3.1.2, SQLite | 分析、渲染、Web 服务 |
| 前端 | Bootstrap 5, Font Awesome, 原生 JS | 响应式 Web 界面 |
| 嵌入式 | ESP32-S3, GxEPD2, Arduino | 墨水屏驱动与低功耗管理 |
| 部署 | Docker, systemd, crontab | 容器化与定时任务 |

## 阶段 7 在线配置与任务快照

- `SettingDefinition` 与 `SETTING_REGISTRY` 集中声明配置类型、范围、枚举、敏感性、可编辑性、重启要求和生效范围；
- `SettingsRepository` 使用短连接读取 `app_settings` 全局版本，并在单一立即写事务中提交配置、版本和 `app_settings_audit` 审计；
- `ConfigurationService` 每次读取先检查轻量版本，版本变化才重载完整配置，因而 Web 和独立工作进程可跨进程发现更新；
- 数据库只允许保存注册表中明确可热更新且无需重启的配置；锁定的系统、网络与安全项仍只来自启动环境。敏感项的真实值不会进入管理视图、审计或任务快照，其中 `API_KEY` 可在线只写覆盖并以明文存于数据库；
- `admin_jobs` 与 `admin_maintenance_jobs` 在首次认领事务中按任务类型固化配置版本和作用域快照。租约恢复与自动重试沿用原快照；**人工重试会清空 `started_at`，因此下次认领按当前配置重新固化快照**——管理员改完配置点重试就是想用新值；仅升级前已经启动且保持 `0/{}` 的历史任务按当前配置兼容执行。

## 阶段 8 数据库门禁与部署拓扑

- 直接运行 Web 服务、独立工作进程或 systemd 单元时，应用只断言当前结构，不自动迁移；容器镜像统一先执行 `python -m src.container_entrypoint`，仅在 `DB_PATH` 指向的数据库完全不存在时创建父目录、取得同目录初始化锁并完整迁移，已有数据库只做严格结构检查；
- 通用容器入口准备成功后通过 `os.execvp()` 原样转交目标命令，准备失败则不启动目标服务。锁只负责串行化并发进程，每个等待者取得锁后都会重新检查数据库；
- `check-schema` 是只读门禁，调用 `assert_current_schema()`；迁移版本集合必须恰好为 1 至 50，且每个版本的名称与 SQL 文件 SHA-256 校验值必须匹配当前程序内置迁移；
- `migrate` 在执行任何待迁移 SQL 前复用同一台账校验。未来版本（例如 51）或同版本不同名称、不同校验值的分叉历史会拒绝迁移、`check-schema` 和应用启动；高版本数据库必须先升级程序，禁止旧程序继续写库；
- systemd 使用 `inktime-schema.service`、`inktime-server.service`、`inktime-worker.service` 三单元，结构门禁只检查、不创建数据库；
- Docker Compose 使用 schema、server、worker、analyzer、render-7c、render-133c 六服务，后三个工具服务位于 `tools` profile。`inktime-schema` 先经镜像入口初始化或校验，再执行 `check-schema`；其余服务等待 schema 成功并在各自启动时再次经过入口校验；
- 2026-08-18 已完成 Podman `linux/amd64` 单镜像完整无缓存构建、镜像内容门禁、新卷首次迁移 50 个版本、容器重启和移除初始化令牌后的同卷重建验收；尚未完成 Linux systemd 实机安装或 Docker Compose 六服务整组验收。


## 管理员认证组件

阶段 2 在 Web 服务器内新增独立认证分层，公开相册路由保持原有 URL、方法和响应契约；后续首次设置能力复用同一认证边界：

- `src/server/extensions.py`：创建未绑定的 Flask-Login `LoginManager` 与 Flask-WTF `CSRFProtect`，由应用工厂绑定。
- `src/server/auth.py`：管理员身份、凭据校验、初始化令牌安全加载与常量时间比较、SQLite 跨进程滑动窗口、安全 `next` 校验、普通管理员创建命令和首管理员创建服务。
- `src/server/forms.py`：携带跨站请求伪造令牌的登录表单与首次设置表单；首次设置要求密码二次确认。
- `src/server/repositories/admin_user_repository.py`：复用请求级数据库连接执行参数化查询；首管理员创建使用独立立即写事务，在同一事务中检查全表为空并插入密码哈希，并发请求只能成功一个。
- `src/server/blueprints/admin.py`：登录、退出、`/admin/setup` 和后台页面/接口路由。管理员表为空时设置页匿名可见；存在任意管理员后 GET 与 POST 都返回 HTTP 404。
- `src/server/templates/admin/login.html`、`src/server/templates/admin/setup.html`：登录页首次设置引导和不依赖外部内容分发网络的设置页面。成功创建后跳转登录页，不自动建立登录会话。
- 生产应用还会拒绝空、示例值 `inktime` 或少于 24 个字符的 `DOWNLOAD_KEY`；开发和测试可留空。上传总请求体上限由规范化后的文件数乘单文件字节上限，再加 1 MiB multipart 元数据预算派生。

初始化令牌支持环境变量和 UTF-8 普通文件两种互斥来源，不写入数据库或 Flask `app.config`。完成首次设置后必须删除令牌来源并重启进程，清除认证服务内存中持有的令牌字节。

认证固定依赖 Flask-Login==0.6.3 负责会话身份，Flask-WTF==1.3.0 负责表单和跨站请求伪造保护。

## 依赖项

### 自动测试

- `npm test` 是完整自动测试的唯一入口，底层使用 Python 标准库 `unittest`，不引入 pytest 或新的运行依赖。
- `package.json` 不再包含仅供失效手工脚本使用的 `node-fetch`；公开接口测试改用 Flask 测试客户端，不启动 Node.js 或真实 HTTP 服务。

### Python 依赖（requirements.txt）

- Flask==3.1.2 — Web 框架
- Flask-Login==0.6.3 — 管理员会话认证
- Flask-WTF==1.3.0 — 表单与跨站请求伪造保护
- requests==2.32.5 — HTTP 客户端（调用视觉语言模型 API）
- Pillow==12.0.0 — 图像处理
- pillow-heif==1.5.0 — HEIC/HEIF 解码，iPhone 默认拍照格式；上传时转码为 JPEG
- python-dotenv==1.0.0 — `.env` 文件加载
- lunar-python==1.4.8 — 农历、节气、干支、传统节日，**纯离线计算**
- zhconv==1.4.3 — 繁简转换（维基「历史上的今天」返回繁体），纯离线
- waitress==3.0.2 — 生产级 Web 服务，`python -m src.server.run_server` 为本地、systemd 和 Docker 的统一入口

### 可选 Python 依赖

- openai（可选） — 分析脚本会尝试导入，失败时自动退回 requests 调用，功能不受影响，通常不需要装

### 系统依赖（可选）

- exiftool — 更完整的 EXIF/GPS 提取
  - macOS: `brew install exiftool`
  - Linux: `sudo apt-get install -y libimage-exiftool-perl`
  - 缺失不致命，但 GPS 会不全，影响城市名与旅行加成
- sqlite3 命令行工具 — 仅用于手工查库，`sudo apt-get install -y sqlite3`。
  没装也可以用 `./venv/bin/python -c "import sqlite3; ..."` 替代
- 中文字体 — 渲染文案必需，缺失会渲染成豆腐块且不报错。
  Ubuntu 通常自带 `/usr/share/fonts/opentype/noto/NotoSansCJK-Regular.ttc`，
  用 `.env` 的 `FONT_PATH` 指定；没有时 `sudo apt-get install -y fonts-noto-cjk`


### 硬件依赖

- ESP32-S3-N8R8（8MB Flash + 8MB PSRAM）
- 7.3 寸四色墨水屏 EL073TS3 或 13.3 寸六色屏
- GxEPD2 Arduino 库
