# 06 - ESP32 硬件模块

## 概述

ESP32 模块负责从服务器下载渲染好的 .bin 文件，驱动墨水屏显示，并通过 Deep Sleep 实现超低功耗。

**固件文件**：
- `esp32/ink-display-7C-photo/ink-display-7C-photo.ino` — 7.3 寸四色版
- `esp32/ink-display-133C-photo/ink-display-133C-photo.ino` — 13.3 寸六色版

## 硬件规格

### 主控

- 芯片：ESP32-S3-N8R8
- Flash：8MB
- PSRAM：8MB（7.3 版必须，用于存储 384000 字节整帧 framebuffer；13.3 版按行流式喂屏，不占整帧）
- 工作频率：80MHz（降频省电）

### 屏幕（7.3 寸四色版）

| 参数 | 值 |
|------|-----|
| 型号 | EL073TS3 (GDEY073D46) |
| 分辨率 | 800×480（逻辑竖屏 480×800） |
| 颜色 | 黑/白/红/黄（4 色） |
| 接口 | SPI（单芯片） |
| 驱动库 | GxEPD2 (`GxEPD2_7C<GxEPD2_730c_GDEY073D46, HEIGHT/4>`) |
| 连接器 | 49-pin FPC |

### 屏幕（13.3 寸六色版）

| 参数 | 值 |
|------|-----|
| 面板 | 13.3E6（1200×1600，六色，4bpp） |
| 分辨率 | 1200×1600（`FB_BYTES=960000`，半屏 `HALF_BYTES=480000`） |
| 颜色 | 黑/白/红/黄/蓝/绿（6 色） |
| 接口 | SPI，左右两颗芯片（CS_M / CS_S）分别驱动半屏 |
| 驱动 | 厂商 `epd.h` 链路（`EPD_dispInit`/`EPD_dispLoad`，`EPD_dispIndex=50`） |

> 13.3 寸不用 GxEPD2，也不在内存里维护整帧 framebuffer：固件按行（300 字节/半屏行）
> 从 HTTP 流直接喂给 `EPD_dispLoad`，因此不需要为整帧分配 PSRAM。

### 引脚定义（7.3 寸四色版）

| 引脚 | GPIO | 功能 |
|------|------|------|
| BUSY | 14 | 屏幕忙状态（输入） |
| RST | 13 | 屏幕复位（输出） |
| DC | 12 | 数据/命令选择（输出） |
| CS | 11 | SPI 片选（输出） |
| SCLK | 10 | SPI 时钟（输出） |
| DIN (MOSI) | 9 | SPI 数据（输出） |
| FACTORY_RESET | 38 | WiFi 重置按键（`INPUT_PULLUP`，低电平有效） |

### 引脚定义（13.3 寸六色版）

| 引脚 | GPIO | 功能 |
|------|------|------|
| BUSY | 25 | 屏幕忙状态（输入） |
| RST | 26 | 屏幕复位（输出） |
| DC | 27 | 数据/命令选择（输出） |
| CS_S | 2 | 从芯片片选（右半，GPIO2 为 strapping，固件早期用 `INPUT_PULLUP` 稳压） |
| CS_M | 15 | 主芯片片选（左半） |
| SCLK | 13 | SPI 时钟 |
| MOSI | 14 | SPI 数据 |
| PWR_ON | 32 | 面板外部供电使能（高电平开） |
| FACTORY_RESET | 35 | WiFi 重置按键（`INPUT`，input-only 无内部上下拉，需外部电阻，低电平有效） |

### 按键功能

| 按键 | 功能 |
|------|------|
| SW1 (RESET) | 重启设备，立即拉取并显示照片 |
| SW2（7.3=GPIO38 / 13.3=GPIO35） | 按住 SW2 再按 SW1 → 上电清空 NVS，重新配网 |

## 固件工作流程

两版 `setup()` 结构一致（13.3 版另在最早期稳定 GPIO2/CS 线）：

```
setup() {
  1. 释放所有 GPIO hold（从 Deep Sleep 恢复）
  2. 降频到 80MHz
  3. 检查恢复出厂引脚（7.3=GPIO38 / 13.3=GPIO35）是否按下 → 是则清空 NVS 并复位 WiFi 驱动
  4. randomSeed(esp_random())，从 NVS 加载配置
  5. 无有效配置（ssid 为空）→ 进入 AP 配网模式
  6. 连接 WiFi（超时 15s）→ 失败则进入 AP 配网
  7. NTP 同步时间；成功则把当前 epoch 存入 NVS（last_epoch），供下次估算休眠
  8. 下载并显示：
     - 7.3：下载 photo_{random(0..4)}.bin 到 PSRAM framebuffer，再逐像素刷屏
     - 13.3：初始化面板，按行流式下载 _L.bin + _R.bin 直接喂芯片，最后统一 show()
  9. 计算到下次刷新时间点的分钟数（sleepUntilNextSchedule）
  10. 进入 Deep Sleep
}
loop() {}   // 空，全部逻辑在 setup 里跑完就休眠
```

时间处理细节：`syncTime` 最多轮询 30 次（7.3 每次 500ms、13.3 每次 1000ms），用
`configTime` 拉 `pool.ntp.org` / `time.nist.gov` / `ntp.aliyun.com` 三个源。若首次没同步到时间，
下载显示后会再试一次 `syncTime`；仍失败则休眠固定 1440 分钟（一天）。

## NVS 存储项

命名空间固定为 `dashcfg`，通过 `Preferences` 读写：

| 键 | 类型 | 含义 |
|----|------|------|
| `ssid` | String | WiFi SSID（为空即视为「无有效配置」） |
| `pass` | String | WiFi 密码 |
| `hostport` | String | 服务器 `host:port` 或含 `http(s)://` 的地址 |
| `tz` | Int | 时区偏移小时（-12..14，默认 8） |
| `hour` | UChar | 每日刷新整点（0..23，默认 8） |
| `rot180` | Bool | 画面旋转 180°（7.3 生效；13.3 保留字段不实现） |
| `last_epoch` | ULong | 上次 NTP 同步到的 epoch，AP 超时与无时间时据此估算休眠 |

## AP 配网模式

### 触发条件

- 首次启动（NVS `ssid` 为空，`cfg.valid=false`）
- WiFi 连接失败（15s 超时）
- 上电时按住恢复出厂引脚（7.3=GPIO38 / 13.3=GPIO35）→ 先清 NVS 再进 AP

### 配网流程

1. `wifiHardResetForPortal()` 复位 WiFi 栈并切到 `WIFI_AP_STA`、关省电
2. 开启 AP 热点：`InkTime-{MAC 低位 4 位十六进制}`，密码 `12345678`
3. 启动 WebServer（端口 80），注册 `GET /`（配置页）与 `POST /save`
4. 用户连接 AP，访问 `http://192.168.4.1/`
5. 配置页字段：WiFi SSID（扫描下拉或手填）、密码、服务器 `host:port`、每日刷新整点（0-23）、
   时区（-12..+14）、画面旋转 180°（13.3 版标注「暂不实现，仅保留字段」）
6. 保存写入 NVS 后 `ESP.restart()` 自动重启

### AP 超时保护

进入 AP 模式后 5 分钟无操作 → 自动进入 Deep Sleep 到下一个刷新点，避免持续耗电。

## 低功耗设计

### Deep Sleep 配置

- 关闭 WiFi/BT
- 关闭 RTC 外设、慢速内存、快速内存
- EPD 引脚设为 INPUT_PULLDOWN 并 hold（7.3：BUSY/RST/DC/CS/SCLK/DIN；13.3：另含 CS_M/CS_S/MOSI/PWR_ON）
- RTC GPIO 隔离（`rtc_gpio_isolate`）
- 定时器唤醒（到下一个刷新时间点，`sleepUntilNextSchedule` 计算分钟数，钳制在 1..1440）

### 功耗数据

| 状态 | 电流 |
|------|------|
| Deep Sleep | < 1mA |
| WiFi 活跃 | ~80-300mA |
| 屏幕刷新 | ~50mA |

### 续航估算

5000mAh 电池，每天唤醒一次（约 30 秒活跃）：
- 日均消耗 ≈ 1mA × 24h + 200mA × 30s/3600 ≈ 25.7mAh
- 理论续航 ≈ 5000 / 25.7 ≈ 195 天（约半年）

## 下载逻辑

两版都随机取 `idx = random(0, DAILY_PHOTO_COUNT)`（`DAILY_PHOTO_COUNT=5`，即 0..4），URL 前缀由固件常量
`DAILY_PHOTO_PATH_PREFIX` 定义，其中的路径口令必须与服务端 `DOWNLOAD_KEY` 一致
（固件默认值 `.../yourdownloadkey/...` 为占位，烧录前必改）。若 `hostport` 已带 `http(s)://`
则直接用，否则自动补 `http://`。

### 7.3 寸四色

1. URL：`http(s)://{hostport}/static/inktime/{key}/photo_{idx}.bin`
2. 在 PSRAM（失败退内部 RAM）分配 `FB_WIDTH*FB_HEIGHT = 384000` 字节 framebuffer
3. HTTP GET 流式读入 framebuffer；下载超时 60 秒
4. 校验：读满字节数必须等于 384000，否则视为失败
5. 失败则跳过显示直接休眠

### 13.3 寸六色

1. 左半 URL：`.../photo_13in3_6c_{idx}_L.bin`，右半 `..._R.bin`（不用 `_FULL.bin`）
2. 先 `initEpd13in3e()`（最多重试 3 次，含硬件断电重上电）
3. 左半 CS_M 低、右半 CS_S 低，发 `0x10` 命令后**按行**流式下载（每半屏行 300 字节，共 1600 行 =
   480000 字节），逐行 `EPD_dispLoad`，不落盘、不缓冲整帧
4. 单次 HTTP 超时 20 秒、整体下载超时 240 秒；content-length 与 480000 不符视为失败
5. 两半都传完后关 WiFi/BT 再 `show()` 刷新，降低刷屏时的电源/EMI 尖峰

## 墨水屏显示

### 7.3 寸四色（GxEPD2）

1. `SPI.begin(SCLK=10, MISO=-1, MOSI=9, CS=11)`
2. `display.init(...)`；`rotate180` 为真时 `setRotation(3)`，否则 `setRotation(1)`
3. 分页刷新：`framebuffer[y*480+x]` 索引 → 调色板颜色（0=黑,1=白,2=红,3=黄）逐像素 `drawPixel`
4. `display.hibernate()` 进入屏幕休眠

### 13.3 寸六色（厂商 epd.h）

1. `initEpd13in3e()`：使能 `PIN_EPD_PWR_ON`、`EPD_initSPI()`、硬复位脉冲、`EPD_dispIndex=50`、
   `EPD_dispInit()`（失败重试 3 次，仍失败则死循环停机）
2. 左右半屏分别选 CS_M / CS_S，发 `0x10` 后按行 `EPD_dispLoad(lineBuf, 300)` 送数据（下载即显示，无 framebuffer）
3. 两半送完 `EPD_dispMass[EPD_dispIndex].show()` 统一刷新
4. 此版不实现 180° 旋转（`rot180` 仅保留配置字段）

## 编译与烧录

### Arduino IDE 配置

1. 安装 ESP32 Arduino Core
2. 选择开发板：ESP32-S3（开启 PSRAM：OPI PSRAM）
3. 安装库：GxEPD2
4. Flash Size：8MB
5. Partition Scheme：默认

### 烧录方式

- UART 串口烧录（推荐）：连接 H1 测试焊盘
- USB 烧录：需焊接 R2/R3/C5/C6，将 BOOT 引脚短接 GND 后上电

### 关键修改项

烧录前必须修改：
- `DAILY_PHOTO_PATH_PREFIX` — 路径中的口令段必须与服务端 `DOWNLOAD_KEY` 一致
  （固件源码注释里仍写「同步 config.py」，实为历史遗留，现在配置源是 `DOWNLOAD_KEY`）
- 引脚定义 — 如使用不同开发板
- 屏幕构造函数 / 驱动 — 如使用不同型号屏幕（7.3 改 GxEPD2 构造函数，13.3 改 `EPD_dispIndex`）
